

### 实现与评估方案

#### 实现方案
第一步是离线生成与验证的具体实现。我们首先输入漏洞代码和攻击样本，利用大模型辅助提取出触发漏洞所需的只读判断条件。提取出的逻辑会被转换为C代码，并编译成eBPF字节码。为了绝对保证防护逻辑不引入新风险，我们实现了一个极简的检查器。该检查器会严格扫描生成的字节码，强制拒绝任何包含目标内存写操作的指令，同时拒绝向后跳转指令以防止死循环。只有通过检查器的纯只读字节码，才允许部署到系统中。

第二步是跨平台入口拦截的具体实现。核心目标是在原函数真正执行前将其暂停，并完整提取当前的CPU寄存器状态（包含函数参数）。针对不同平台我们采用不同机制：在Linux内核中，直接复用系统原生的kprobes机制进行拦截；在Linux用户态中，优先使用LD_PRELOAD进行注入，并配合轻量级的Inline Hook替换函数头部的指令；在FreeBSD系统中，则通过手动替换目标函数入口指令来实现基础的Trampoline Hook。

第三步是影子执行与裁决的具体实现。我们将自定义的eBPF虚拟机直接嵌入到上述拦截模块中。当拦截触发时，系统将提取到的寄存器状态传入虚拟机，开始运行生成的字节码。虚拟机内部采用特制的安全读内存接口：内核态使用免错拷贝机制（如copy_from_kernel_nofault），用户态则依靠捕获段错误信号（SIGSEGV）来容错，确保即使读到无效内存，宿主系统也绝对不会崩溃。执行结束后，如果虚拟机判定当前调用安全，系统会恢复被覆盖的原指令，让程序继续正常执行；如果判定为攻击，系统会直接将返回寄存器（如RAX）修改为预设的错误码，并强制执行返回指令，确保存在漏洞的原函数体一行都不会被执行。

#### 测试方案

首先是防御有效性与泛化测试的具体执行。我们将挑选涵盖越界读写、释放后重用、整数溢出等多种不同漏洞类型的真实历史CVE，且目标覆盖Linux内核、Linux用户态以及FreeBSD系统。针对每一个选定的CVE，我们会运行其对应的真实漏洞利用脚本（PoC）。预期结果是，系统能够在各种复杂的真实场景下，精准识别出恶意请求并成功阻断攻击，证明防御方案的有效性与普适性。

其次是误杀与系统健壮性测试的具体执行。一方面，我们将运行目标软件官方提供的正常业务测试集，核对正常功能是否受影响，以此证明精准拦截方案能够保留更多正常功能，明显优于直接禁用整个函数的SWRR粗暴方式。另一方面，我们会特意人为引入边界异常情况（如让大模型生成包含无效指针读取的瑕疵代码），验证虚拟机的安全读机制能否有效容错，证明防护模块自身在遇到意外时也绝对不会导致宿主系统崩溃。

最后是性能开销测试的具体执行。我们分别测量无防护、SWRR（直接返回错误码）和 Shadow Execution 三种模式下的平均延迟、p95 延迟、p99 延迟和吞吐量。对于 Shadow Execution，我们额外记录每次 VM 执行的 eBPF 指令数和安全内存读取次数。该实验用于说明，Shadow Execution 虽然比直接返回错误码的 SWRR 更复杂，但其性能开销仍然在可接受的范围内。


### 详细实现步骤
参考这个目录布局：

```
AutoShield/
├── offline/                 # 【步骤一】离线生成与验证
│   ├── gen_rule.py          # 核心脚本：连大模型、套模板、调编译器
│   ├── verifier.py          # 极简检查器：扫描 eBPF 禁写、禁死循环
│   └── template.c           # 注入逻辑的 C 代码骨架
│
├── runtime/                 # 【步骤二、三】数据平面运行时 (C语言，扁平化)
│   ├── autoshield.h         # 统一头文件：结构体定义与宏
│   ├── vm.c                 # 自定义 eBPF 虚拟机解释器与裁决逻辑
│   ├── safe_mem.c           # 特制安全读接口 (内核 nofault / 用户态 SIGSEGV)
│   ├── hook_user.c          # Linux 用户态拦截 (LD_PRELOAD + Inline)
│   ├── hook_kernel.c        # Linux 内核态拦截 (kprobes)
│   ├── hook_freebsd.c       # FreeBSD 拦截 (Trampoline)
│   └── Makefile             # 统一编译脚本
│
├── examples/                # 靶场示例
│   ├── user_demo/           # 用户态漏洞靶场 (包含 vuln_server, poc, normal_req)
│   └── kernel_demo/         # 内核态漏洞靶场 (包含 vuln_module, poc, normal_req)
│
└── tests/                   # 【测试方案】三大核心测试
    ├── test_security.py     # 1. 有效性测试：跑 PoC，断言拦截成功
    ├── test_robustness.py   # 2. 健壮性测试：跑正常请求防误杀 + 注入非法程序看是否拒绝
    ├── test_perf.py         # 3. 性能测试：对比无防护与 Shadow Exec 的延迟
    └── ebpf_cases/          # 独立 eBPF 指令文本用例
```
